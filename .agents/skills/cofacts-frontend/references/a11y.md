# Accessibility

From the designer's **Cofacts 無障礙與前端實作指南** (version 2026-10-08, matching Penpot
`Cofacts-2026 (26-10-08)`). Goal: friendly and usable, not certification. Contrast thresholds:
4.5 for normal text, 3 for large text, icons and borders. Where the guide and Penpot disagree,
Penpot wins and the guide gets fixed.

## Five rules

- **R1 — Status is text, never color alone.** Fact-check results use text + a shape icon + color:
  含有不實訊息 (octagon ✕), 含有正確訊息 (circle ✓), 含有個人意見 (square ⋯),
  不在查證範圍 (triangle !). Wording is always 「含有不實訊息」, never 「含有錯誤訊息」.
  The icon is `aria-hidden`; the text is the content. Icon-only places need an `aria-label`.
- **R2 — Brand yellow is a background, never text.** Yellow on white is 1.76. As a background
  under dark text it is 10.09. Logos are exempt.
- **R3 — Semantic names only.** `text-text-primary`, never `neutral-900`. (Enforced: primitives have no
  utilities.) Only exception: the UI-system swatch wall in Penpot.
- **R4 — Flipping pairs with flipping, fixed with fixed.** A background and its foreground flip
  together or stay together. Name check: on `surface-dark` use only `-on-dark`; on
  `surface-inverse` only `-inverse`. `surface-inverse` is **not** "always dark" — it turns light
  in dark mode; use `surface-dark` for always-dark. Status badges: `bg-status-*` with
  `text-text-on-status` (both flip).
- **R5 — Disabled = default colors + `opacity: 0.5`.** No separate grey. Add `disabled` or
  `aria-disabled="true"`; don't rely on the fade alone. Disabled controls are exempt from contrast.

## Typography

Noto Sans TC; sizes 36 / 28 / 24 / 18 / 16 / 14 / 12; letter-spacing 0. Every text uses a
typography token: `heading-*` for titles, `body-*` / `caption` for wrapping text, `ui-*` for
single-line UI text (buttons, labels, tabs). 12px is the minimum and only for labels, notes and
chart axes. 18px bold is **not** large text, so status titles need 4.5 (hence 700-step red/green).

## Focus

One global `:focus-visible` rule (`src/styles/global.css`): 2px gap → 2px dark inner ring
(`border-focus`) → 4px brand-yellow outer ring, 8px total, following the element's radius.
Never blue (blue means 含有個人意見, and is 2.71 on the yellow button). Inside fixed-dark areas
(Footer, intro header, ActionPanel, mobile menu) put `data-surface="dark"` on the container.

## Interaction states

| State             | How                                                                                                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hover             | the component's hover variant                                                                                                                       |
| Active / selected | `active`, `normal-active`, `Selected` variants (selected filter chip = Badge `normal-active`)                                                       |
| Focus             | global ring; may combine with active                                                                                                                |
| Disabled          | R5                                                                                                                                                  |
| Error             | Input `Invalid`: `aria-invalid="true"`, red = `status-incorrect` (also for destructive buttons), plus a text message linked with `aria-describedby` |

Inputs: white background (`bg-surface-base`, placeholder `text-text-tertiary` is 4.83 on white, fails on grey).
Active input = `border-border-accent` (yellow) border, not a background change; yellow alone is too
weak, so the focus ring must show too. Never use placeholder as the label.

Touch targets: ideal 44px. Buttons are Large 44 / Medium 36 / Small 28 / Icon-Touch 32 (mobile
hamburger and close). Exceptions: desktop nav "回報可疑訊息" 40 (fills the nav), mobile menu
full-width buttons 44. Smaller targets may grow their hit area with transparent padding or `::after`.

## Components: semantics and keyboard

| Component            | HTML / ARIA                           | Keys          | Notes                                                                      |
| -------------------- | ------------------------------------- | ------------- | -------------------------------------------------------------------------- |
| Button               | `<button>`                            | Enter, Space  | `Icon = Only` requires `aria-label`; Secondary uses `bg-surface-secondary` |
| Button AI            | `<button>`                            | Enter, Space  | loading: `aria-busy="true"`                                                |
| Toggle (favorite)    | `<button aria-pressed>`               | Enter, Space  |                                                                            |
| Badge as filter chip | `<button aria-pressed>`               | Enter, Space  | `normal-active` = selected                                                 |
| Switch               | `<button role="switch" aria-checked>` | Space         | title bound with `<label>`                                                 |
| Checkbox, RadioGroup | native `<input>`                      | Space, arrows | radios in `<fieldset>` + `<legend>`                                        |
| Input, Textarea      | native                                | —             | `aria-invalid` when invalid                                                |
| Select               | native `<select>` first               | arrows        | custom ones implement listbox                                              |
| Icon                 | `<svg aria-hidden="true">`            | —             | meaning lives on the button or text                                        |
| Avatar               | `<img alt>`                           | —             | alt = user name; level "Lv99" as text                                      |

Special interactions:

- **Nav:** `<nav aria-label="主選單">`; current page `aria-current="page"` (NavItem `hover`
  underline); "99+" is read out ("最新查核，99 則以上新訊息"). Header bottom 1px `border-border-subtle`;
  Footer top 1px `border-border-on-dark`.
- **Mobile menu:** hamburger `aria-expanded` + `aria-controls`; focus moves to the first item;
  Esc closes and returns focus to the hamburger.
- **EditorTab:** tabs pattern (`tablist`/`tab`/`tabpanel`), arrow keys, `aria-selected`.
- **ActionPanel:** desktop `<nav aria-label="本頁索引">` with anchor links; mobile tab row
  scrolls horizontally; 「查核闢謠」 is a floating button outside the row.
- **OriginalMessage:** header is `<button aria-expanded aria-controls>`. Mobile expanded max
  height ~240px with inner scroll, `overscroll-behavior: contain`, `tabindex="0"`; collapses when
  the editor gets focus. Bottom fade: `surface-base` → transparent.
- **Mobile filter panel, draft drawer:** `<dialog>` or `role="dialog" aria-modal="true"`, focus
  trapped, Esc closes and restores focus, scrim `bg-overlay-scrim`. Filter panel: sticky 「清除」 and
  「顯示 N 則結果」; choices change only panel state until 「顯示 N 則結果」 applies them; announce N
  with `aria-live="polite"`; leave 68px at the bottom of the options. Desktop filters apply on click.
- **AI input loading:** 「正在查看有沒有人回報過…」 in `role="status"`.
- **Charts:** chart `aria-hidden`, plus a text summary ("近 30 日網頁瀏覽 43 次、LINE 詢問 2 次");
  legend names each line. Line colors: `var(--color-chart-series-1/2)`.
- **閱讀全文:** `<button aria-expanded>`, not an `<a>` without `href`; text and arrow `text-text-link`.
- **Long URLs:** `overflow-wrap: anywhere`.

## Not covered by the guide (check while coding)

- Focus management for drawers and bottom sheets (open → move in, close → return to trigger).
- Icon-only buttons in the old UI lack `aria-label` (hamburger, send, attach, notifications).
- Clickable backdrops: use `<button>` or Base UI Dialog.
- AI streaming: `aria-live="polite"` announcing start / done / error only, not every token.
  After submit/report success, move focus to the result heading.
- `prefers-reduced-motion` for landing animations, view-transition drawers, typing indicator.
- Measure contrast of text over images or gradients (home hero, impact banner).

## Known exceptions (decided, not bugs)

LINE green button with white text (2.26, LINE brand rules) · Footer GOV logo red (hard-coded) ·
brand logos exempt from R2 · chart's yellow line (data, not text; legend + summary) · Flag fold
`surface-accent-fold` (decoration) · purple annotation frames exist only in Penpot · gradients
are hard-coded in Penpot and rebuilt with tokens in code · archive and cover pages out of scope.

## Checklist for a UI PR

- [ ] Light and dark both checked in Storybook
- [ ] Every status shows text + icon (R1); no yellow text (R2); no primitives (R3); pairs match (R4)
- [ ] Disabled uses opacity + `disabled`/`aria-disabled` (R5)
- [ ] Keyboard: every action reachable, visible focus, Esc closes overlays, focus returns
- [ ] Icon-only buttons have `aria-label`; decorative icons `aria-hidden`
- [ ] Inputs have labels; errors have text linked by `aria-describedby`
- [ ] Specs above for any special interaction this PR touches
